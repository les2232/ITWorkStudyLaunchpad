# IT Work Study Launchpad Training Paths

## Purpose

Training paths define what each new IT work-study student should complete after the auto-scored part of the pre-assessment.

The goal is to give each student the right level of support based on their starting knowledge, confidence, and readiness.

The training paths should help students:

- Build beginner IT vocabulary
- Understand common IT workflows
- Learn what tasks are beginner-safe
- Know when to ask for help
- Practice documentation and draft ticket notes
- Prepare for shadowing and beginner tasks

---

## Placement Levels

| Auto-Scored Pre-Assessment Score | Level | Recommended Path |
|---:|---|---|
| 0-39 | Beginner | Full IT Foundations path |
| 40-69 | Developing | Foundations + Day 1 checklist |
| 70-84 | Ready to Shadow | Day 1 checklist + shadowing |
| 85-100 | Advanced Beginner | Faster path, still complete required modules |

These levels are not pass/fail labels. They are used to recommend the right starting point.

Free-response answers should still be reviewed by a mentor or supervisor. A high auto-scored result does not mean all written answers have been reviewed.

---

## Work Style and Role Alignment

The pre-assessment also includes a separate Work Style and Role Alignment section. This does not change the technical readiness score or training path.

Use it as a supervisor planning signal for the question: Which environment would help this student succeed fastest?

Possible outputs:

- IT Launchpad
- Hybrid IT/User Support
- Student Services Exploration
- Structured Shadowing

Admissions, Advising, front desk support, and other student services environments should be presented as positive alignments with communication, process guidance, and structured support strengths, not as fallback options.

## Path 1: Beginner

### Who This Is For

Students who have little or no prior IT experience and may not yet understand common terms like domain, imaging, SCCM, tickets, or asset tags.

### Main Goal

Help the student build basic IT vocabulary and confidence before expecting them to understand workflows.

### Required Items

1. What Does IT Do?
2. Common IT Words
3. Domain Basics
4. Configuration Manager Overview
5. Computer Imaging Overview
6. Ticket Basics
7. Asset Tag Basics
8. Hardware Basics
9. How to Ask for Help
10. Escalation Rules
11. Day 1 Checklist
12. Shadow a mentor or IT tech

### Mentor Focus

The mentor should explain:

- Basic IT vocabulary
- How department workflows are organized
- What tasks the student is allowed to do
- What tasks require approval
- How to ask for help without feeling embarrassed

### Completion Criteria

The student should be able to:

- Explain basic IT terms in simple language
- Identify beginner-safe checks
- Ask for help clearly
- Complete module knowledge checks
- Complete the Day 1 checklist
- Shadow a mentor or IT tech
- Understand when not to guess

---

## Path 2: Developing

### Who This Is For

Students who are comfortable using computers but are new to IT department workflows.

### Main Goal

Help the student connect basic computer knowledge to real IT support workflows.

### Required Items

1. Day 1 Checklist
2. Common IT Words
3. Hardware Basics
4. Imaging Overview
5. Ticket Basics
6. Escalation Rules
7. How to Ask for Help
8. Shadowing
9. Scenario Practice

### Mentor Focus

The mentor should explain:

- How tickets are handled
- What good documentation looks like
- How imaging fits into the department workflow
- When to escalate instead of continuing alone

### Completion Criteria

The student should be able to:

- Complete basic onboarding tasks
- Understand common workflow terms
- Draft simple ticket notes for mentor review
- Perform beginner-safe checks
- Complete module knowledge checks
- Escalate when unsure

---

## Path 3: Ready to Shadow

### Who This Is For

Students who have some relevant experience and understand several basic IT concepts, but still need department-specific training.

### Main Goal

Get the student into shadowing quickly while still covering required expectations and safety boundaries.

### Required Items

1. Day 1 Checklist
2. Department expectations review
3. Confidentiality basics review
4. Imaging Overview
5. Ticket Basics
6. Escalation Rules
7. Shadowing
8. Scenario Practice

### Mentor Focus

The mentor should explain:

- Department-specific workflow
- Local expectations
- Ticketing habits
- Imaging boundaries
- Escalation expectations

### Completion Criteria

The student should be able to:

- Shadow productively
- Ask specific questions
- Follow basic procedures
- Document what they observe
- Complete module knowledge checks for assigned modules
- Recognize when mentor approval is needed

---

## Path 4: Advanced Beginner

### Who This Is For

Students with stronger prior experience, such as previous help desk, computer lab, repair, or customer support experience.

### Main Goal

Move the student through required onboarding efficiently while still confirming they understand local rules.

### Required Items

1. Day 1 Checklist
2. Department expectations review
3. Confidentiality basics review
4. Imaging Overview
5. Escalation Rules
6. Scenario Practice
7. Mentor Check-In
8. Post-Assessment

### Mentor Focus

The mentor should confirm:

- The student understands local workflows
- The student does not assume previous procedures apply here
- The student documents work correctly
- The student escalates according to department expectations

### Completion Criteria

The student should be able to:

- Complete required onboarding
- Explain beginner-safe task boundaries
- Write clear draft notes and mentor summaries
- Complete knowledge checks for assigned modules
- Ask for help when local workflow is unclear
- Complete scenario practice successfully

## Knowledge Gap Routing

Use the pre-assessment results to recommend extra modules.

| Weak Area | Recommended Modules |
|---|---|
| IT Vocabulary | Common IT Words, Domain Basics, Imaging Overview, Configuration Manager Overview |
| Beginner Troubleshooting | Hardware Basics, How to Ask for Help, Escalation Rules |
| Workflow and Escalation | How to Ask for Help, Escalation Rules, Ticket Basics |
| Confidence | How to Ask for Help, Escalation Rules |
| No Prior IT Experience | What Does IT Do?, Common IT Words, Hardware Basics, Ticket Basics |

---

## Required for All Students

Regardless of starting level, every student should complete:

- Day 1 Checklist
- Department expectations review
- Confidentiality basics review
- Assigned module knowledge checks
- Escalation Rules
- Imaging Overview
- Scenario practice when assigned
- Post-Assessment

This ensures every student gets the same safety foundation.

---

## Readiness Approval

Week 1 readiness may be approved by any authorized supervisor.

Before approval, the student should have:

- Completed required items
- Completed assigned module knowledge checks
- Completed Day 1 checklist
- Completed Week 1 checklist items assigned to their path
- Completed scenario practice
- Completed post-assessment
- Demonstrated safe escalation judgment

Readiness does not mean the student is fully trained. It means the student is ready for beginner-safe tasks with appropriate supervision.

---

## Training Philosophy

The Launchpad should never make students feel punished for starting with less experience.

The system should communicate:

- It is okay to be new.
- It is okay to ask basic questions.
- Do not guess when the task could affect users, data, devices, or access.
- Ask early instead of making preventable mistakes.
- Good documentation helps the whole IT team.
