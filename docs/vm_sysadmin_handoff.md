**389 without TLS is unsuitable for password/simple binds.** This candidate deliberately supports verified direct LDAPS 636 only. Other authentication/transport designs require separate review and implementation, not a configuration bypass. [Microsoft simple-bind requirements](https://learn.microsoft.com/en-us/windows/win32/api/winldap/nf-winldap-ldap_simple_bind), [AD TLS methods](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adts/8e73932f-70cf-46d6-88b1-8d9f86235e81)

LDAPS certificates must identify the directory server, provide Server Authentication usage and chain to a trusted CA. Signing alone provides integrity, not confidentiality. [Certificate requirements](https://learn.microsoft.com/windows-server/identity/ad-ds/configure-ldap-signing-certificates), [LDAP protection layers](https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/ldap-channel-binding)
